Before you use Auto-Backup

Auto-Backup creates mirror backups using Windows' robocopy utility: every source folder you add is copied into every destination folder you add, producing an exact replica of each source.

Mirror means mirror. To keep a destination identical to its source, this tool doesn't just add and update files. It also deletes anything inside the destination's copy that no longer exists in the source. That's what makes it a true backup, and it's also what makes it powerful: pointed at the wrong folder, it will faithfully reshape that folder to match the source, removing whatever doesn't belong.

The tool refuses obviously unsafe setups (overlapping paths, duplicate folder names, mirroring a folder onto itself) and asks for confirmation before every run. Still, double-check your destinations. This tool does exactly what you tell it to.

Ignore This Version

Ignoring hides the update notice in the Home Top Bar and About modal, and stops the About icon pulsing, for . If a newer version is released later, then update notifications are resumed.

To turn version notifications off entirely, use New Version Notification in the General Settings modal.

Enable New Version Notifications

With this setting turned on, Swiss RB Knife makes a single network request to GitHub (once on startup, and once right now as you enable the setting) to check whether a newer release is available to install.

Note: new updates are never auto-installed, nor even auto-downloaded. This feature is what it is, a notification; nothing more, nothing less.

This is the only time the app touches the network. No personal data ever leaves your device; the app otherwise remains fully offline. You can always turn this setting off at any time.

Dirs to Copy

Why is this higher than Total Source Dirs?

Because the backup also creates each source folder itself at the destination. Backing up C:\Photos into D:\Backup produces D:\Backup\Photos. That root folder is one directory the run has to create, on top of everything inside it. One extra root is counted per source, per destination.

Why not just raise Total Source Dirs to match?

Because the two numbers answer different questions. Total Source Dirs describes what exists inside your sources; Dirs to Copy describes the work the next run would do. Nudging the source stats to make the comparison tidier would make them lie about your actual folders.

This button only appears when the two disagree, on incremental runs, where the roots already exist, it stays out of your way.

Copy Speed

What it does

This value is an estimating aid, nothing more. It seeds the Estimated Time shown in the Summary panel, and gives a running backup's progress bar and ETA a starting speed to work with during the first moments of a run, before enough real data has flowed to measure the actual throughput.

What it does not do

It does not limit, throttle, or control the speed of an actual backup in any way. Backups always run at whatever speed your drives can deliver. Setting this to 1 or 10,000 changes only the predictions on this screen, never the backup itself.

It tunes itself

After every successful backup that copies a meaningful amount of data (at least 100 MB), the speed measured during that run is blended into this value (70% old, 30% new), so the estimates steadily converge on your machine's real-world throughput. Small incremental runs are ignored, since they're too brief to measure honestly.

You can still type in your own value at any time; it simply becomes the new baseline that future measurements adjust from.

Resize & Canvas

Resize

Scales each image to fit within the width and height you specify, preserving its aspect ratio. The output will be no larger than the box you define, but its exact dimensions depend on each image's proportions.

If you set only W, images are scaled to that width and height follows proportionally. If you set only H, the opposite applies. If you set both, images fit within that box. Leave both blank to skip resizing entirely. You can still apply a canvas without resizing.

Canvas

Places each (optionally resized) image onto a fixed-size surface filled with the background color. Images smaller than the canvas are padded; images larger than the canvas are cropped.

Use canvas when all output files must share identical dimensions, for example a carousel where every slide must be exactly 1920×1080.

Best practice: the canvas should always be equal to or larger than your largest source image, or your resize target if one is set. If the canvas is smaller, the image will be cropped.
